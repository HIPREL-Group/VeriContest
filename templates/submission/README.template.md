# Submission methodology

This file is optional. Replace the prompts below with your methodology, or delete
the file to keep the methodology private; the disclosures in metadata.yaml are
required either way. All files in this entry are public. Keep confidential artifacts in the agreed
private channel and describe their availability in metadata.yaml.

## System

REPLACE_ME: Describe the system, backend models, tools, stages, and any human
intervention. Include a report or source link when available.

## Generation

REPLACE_ME: Describe the actual task inputs, sampling settings, execution budget,
internal search and repair, final-candidate selection, and feedback used. Record
whether any independent runs were discarded; do not select runs using official
test results. Explain unavailable settings and resource measurements.

## Evaluation

REPLACE_ME: Give commands, dependencies, resource limits, testcase revision,
custom-checker handling, and explanations of failures or unsupported cases.
If no checks have run, say so explicitly and leave component checks at not_run.
Describe the logs and the trajectory format, and any redactions.

## Artifacts and fresh runs

REPLACE_ME: Explain the artifact bundle layout and replay instructions. State
whether fresh system runs can be arranged. Per-result paths start at the bundle
root; include their directory prefixes. If the bundle is pending, explain what
remains to be shared. Do not include credentials.
